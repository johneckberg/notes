## The goal of design patterns is to improve productivity

* S: Single Responsibility Principle
  * A class should have a single responsibility
* O: Open Closed Principle
  * Software Entities should be open for extension but closed for modification
* L: Liskov Substitution Principle
  * You should be able to replace objects of a parent class with objects of a subclass **WITHOUT** breaking the code
* I: Interface Segregation Principle
  * Never be forced to implement an interface that you dont use
* D: Dependency Inversion Principle 
  * High level should depend on abstractions not on low level concrete specifications


## Patterns: Common Principles

* Program to an interface
* Prefer object composition over inheritance: (use has a over needs a when possible; consider the decorator pattern) Consider a tree that has christmas decorations vs a new tree type that needs christmas decorations. Don't overuse constructors 
* Keep objects loosely coupled 
* Encapsulate the concept that varies (strategy pattern)
* Three basic types: Structual, Creational, Behavioral
